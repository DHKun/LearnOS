# 实验类型与概念动画的写法

每种实验类型都写明：适合教什么、状态结构、判分方式、要避开的坑，并附 `http-hands-on` 里的实例和换到其他主题时的例子。一门课最好混用 3～4 种类型，不要每章都是同一种形式。

所有类型都遵守同一套分工：

```text
simulation/<world>.ts   模拟世界：纯函数，输入 → 新状态 / 输出
simulation/labs.ts      每个实验的数据（初始的坏状态、场景、记录）和 gradeXxx()
activities/labs.tsx     界面：调用同一套 grade/evaluate 做即时反馈
validators.ts           严格解析输入 → 调用 gradeXxx()
```

## 目录

1. 修好坏掉的东西
2. 工作台 + 服务端重放
3. 一份配置满足多个场景
4. 从制品里读出答案
5. 诊断一份记录
6. 时间线回放
7. 概念动画的五种画面

## 1. 修好坏掉的东西

**适合**：“为什么不行”类的知识。学生要观察输出、定位原因、改一处再看一次。

**实例**：`url-lab`（片段没有发给服务器、端口写错）、`request-lab`（按书名请求详情返回 404，要先查列表拿到 ID）、`json-lab`（406 → 415 → 400 → 201）。

**状态**：`{ draft, history?, passed }`。提交的是最后一次的输入，服务端重新计算结果。

**要点**：
- 初始状态就是工单里的坏输入，而且可以同时坏好几处。服务器每次只报它最先发现的那个问题，学生每修好一处，错误就往下走一层，这本身就是在教排错的顺序。
- 失败反馈说明“服务器看到了什么”，而不是“你该改什么”。
- 结果面板展示**真实系统实际处理的东西**，比如浏览器真正发出的请求行，而不是学生输入的原文。差异往往就是知识点（片段消失、中文被百分号编码）。

**换到其他主题**：一段乱码文本，选对解码方式才能还原；一个溢出变成负数的游戏金币计数器，改对数据类型；一个算错钱的记账公式，改成用整数“分”来存。

## 2. 工作台 + 服务端重放

**适合**：需要多步操作、会改变状态的知识：先登录再借书、先建分支再合并。

**实例**：`method-lab`（以馆员身份修正书名，PUT 会清空其他字段）、`final-mission`（搜索 → 登录 → 借一本可借的书）。

**状态**：`{ draft, history: Request[], selected, passed }`。界面通过 `replay(history)` 推导出当前世界，不单独存世界状态。提交的是整个 `history`。

**判分**：`replay(history)` 在全新世界里从头执行，检查**最终状态**（7 号书除了书名其余字段不变、小林名下恰好借了第 8 本书）。

**要点**：
- 给出“清空记录并重置”按钮；记录数设上限，比如 20 条，超出后要求重置。
- 需要预设身份时（比如“你已以馆员身份登录”），在世界初始化时完成，并在界面上展示出来（Cookie 罐里已有会话）。
- 旁边实时展示受影响的数据，比如服务器上的数据表，学生每做一步都能看到变化。
- 失败反馈要具体：“书名对了，但作者、年份和原来不一样”。

**换到其他主题**：Git 课的模拟仓库（命令记录 → 重放 → 检查提交图）；文件系统课（命令记录 → 检查目录树）。

## 3. 一份配置满足多个场景

**适合**：几个参数共同作用、彼此有取舍的知识。

**实例**：`cookie-lab`。Path、Secure、HttpOnly、SameSite 要同时满足五个场景：本站可用、从邮件点进来仍保持登录、跨站 POST 不带会话、脚本读不到会话、明文请求不带会话。

**状态**：`{ config, passed }`。`evaluate(config)` 返回每个场景的结果和说明，界面实时显示红绿。

**要点**：
- 场景之间要有**张力**：Strict 会让邮件链接点进来变成未登录，None 又会让跨站 POST 带上会话，最后只有一个组合能全部通过。没有张力的话，学生把所有选项都勾上就过了。
- 题干只写场景和期望，不写哪个属性管哪个场景。
- **配置非法时不能出现虚假的绿色**：比如 Cookie 被拒收后，“不该发送”的场景看起来都安全。这时所有场景都应判为不通过，并统一提示拒收原因。
- 初始配置要让多个场景**因为不同的原因**变红，不要一个错误让所有场景都红。

**换到其他主题**：选择图片格式和压缩率，同时满足清晰度、体积和透明背景的要求；选择数据类型，同时满足取值范围、精度和存储空间。

## 4. 从制品里读出答案

**适合**：读懂某种格式：报文、十六进制转储、日志、提交图。

**实例**：`response-lab`。五份原始响应，答案分别写在 Location、Allow、Retry-After 头、Content-Type 和正文里。

**状态**：`{ answers, passed }`。

**要点**：
- 每题的答案必须能从制品里**读出来**，不靠记忆。
- 尽量用填空，或者用多选列出所有候选值（比如全部 HTTP 方法），避免选项本身暴露答案。填空要做归一化：去空格、接受绝对路径和相对路径两种写法。
- 每题配一句场景说明，让学生知道为什么要读这份东西。

**换到其他主题**：读一段 UTF-8 的十六进制转储，数出有几个汉字；读一张 RGB 色值表，判断哪个颜色更亮。

## 5. 诊断一份记录

**适合**：在真实噪声里分清哪些正常、哪些是问题、哪个是根因。

**实例**：`diagnosis-lab`。模拟的 DevTools Network 面板，逐条判断每个请求，最后找出让“我的借阅”列表变空的那一条。

**状态**：`{ answers: Record<id, option>, root, selected, passed }`。

**要点**：
- 记录里要混入**看起来吓人但其实正常**的条目（304、favicon 的 404、来自内存缓存的请求），这正是新手最容易误判的地方。
- 根因的线索放在**另一条记录**里（登录响应的 `Set-Cookie: Path=/account`），学生要自己对照两条记录。不要把线索附在出错的那条记录上。
- 只提供上下文的条目可以不评分（`answer` 留空，界面显示“不用判断”）。
- 失败提示针对最常见的误判：“304 不是错误”。

**换到其他主题**：一份编码转换日志，找出哪一步把文本弄乱了；一组网络抓包，找出丢包和重传。

## 6. 时间线回放

**适合**：随时间变化的机制：缓存、过期、累积误差、重试。

**实例**：`cache-lab`。为三类资源选 Cache-Control，回放一位读者两天里的 6 次访问和 2 个事件（借书、网站发版），表格标出每次是直接用缓存、304 验证还是下载，以及哪里出现了过期内容。

**状态**：`{ config, passed }`。`simulate(config)` 返回每行结果、目标是否达成以及汇总数字（请求数、流量）。

**要点**：
- 事件插在时间线里显示，不要只写在表格下面。
- 设几个**互相牵制**的目标（不能看到过期内容，又要尽量少发请求，还要保护隐私），允许多组正确答案，但都必须经过权衡。
- 初始配置要让学生在表格里**亲眼看到**问题出在哪一行。

**换到其他主题**：浮点数反复累加，逐步偏离正确值；计数器在第几次加一后溢出。

## 7. 概念动画的五种画面

基础组件见 `components/education/scene-kit.tsx`：`Node`、`Lane`、`MessageLines`、`Chip`、`Segmented`。每个画面都是同一个组件接收 `step`，这样切换步骤时 CSS 过渡才能生效。

| 画面 | 用来展示 | 实例 |
| --- | --- | --- |
| **通道与数据包**：`Node` + `Lane` + `Node`，数据包随 `at` 移动 | 谁发给谁、走到了哪一步 | journey、cookie、cache |
| **状态表变化**：节点里放一张小表，每一步多一行、少一行或改一格 | 操作对数据的影响 | retry（POST 重试多出一笔订单） |
| **报文逐行拼出**：`MessageLines` 配合 `shown`、`focus` 和注释 | 一种格式的结构 | message、redirect |
| **关卡或流水线**：几个节点依次判定，在第几关停下决定结果 | 判定顺序（先认证、后授权） | auth |
| **旁观者视角**：同一过程配一个“第三方看到了什么”的面板 | 安全或隐私边界 | tls |

**要点**：
- 有条件可以对比的，就用 `controls` + `Segmented` 让学生切换（POST 和 PUT、HTTP 和 HTTPS、不同的凭据和资源组合）。
- 窄屏下“节点—通道—节点”改为纵向堆叠：`grid-cols-1 sm:grid-cols-[8rem_1fr_8rem]`。
- 数据包标签保持简短，比如 `GET /`、`201 + Set-Cookie`，细节写在步骤说明里。
- 最后一步给出结论，比如“POST 不幂等：重试造成了重复订单”，用颜色区分好坏，配色使用 token。
