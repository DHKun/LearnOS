# 密码学入门：指纹、锁与印章（`crypto-basics`）

**版本**：`1.0.0` · **格式**：Manifest `schemaVersion: 3` · **学习路线**：《Web 安全入门》第 2 门（前一门《数据库与 SQL》，后一门《登录与会话安全》）

## 设计思路

**立场**：整门课从保护的角度讲。每个实验都是一次防守上的设计或判断；“攻击者能做什么”只用来说明某个设计为什么必要。第 1 章写明：对真实系统的任何测试都必须事先得到授权。

**一个世界**：library.test 的一次安全改造：校验安装包、重新设计密码存法、配置分馆之间的加密、给馆长寄挂失申请、分辨读者群里的公告、看懂六个网站的证书。

**一个比喻**：寄东西。哈希是指纹，对称加密是同一把钥匙的保险箱，公钥是谁都能扣上、只有主人能打开的挂锁，签名是只有你有的印章，证书是公证处盖章担保的身份证明。

## 教学用的玩具算法

`simulation/crypto.ts` 里的算法都是**缩小的教学版本**，在浏览器里真实计算，但**不能保护任何真实数据**：

- `fingerprint()`：64 位玩具指纹函数（FNV + 混合），代替 SHA-256，具有“相同输入相同输出、改一个字大部分位都变”的性质。
- RSA：四个密钥对（周馆长、你、图书馆、仿冒者），模数只有四位数，代替 2048 位密钥。`sign` / `verify` 对内容指纹签名和验证。
- 对称加密的演示：逐块加密（ECB）与带随机数的计数器模式（CTR），用指纹函数模拟分组密码。

## 几处刻意的设计

- **第 2 章**：镜像 B 的文件被篡改，但它页面上的指纹是按篡改后的文件算的，自己和自己对得上；镜像 C 的文件是对的，页面上却写着旧版指纹。只和官网公布的指纹比，才能选对 A、C。
- **第 3 章**：只有“加盐的慢哈希 + 100 毫秒”能同时满足五项：加盐解决相同密码和预算表，慢哈希把逐个尝试的成本推到一年以上，3 秒又会让登录太慢。
- **第 4 章**：三处设置各管一项：逐块加密露出馆徽轮廓，固定随机数让重复的通知密文相同，密钥和密文同寄等于没锁。
- **第 5 章**：钥匙选择由玩具 RSA 真实计算：用你的私钥“加密”谁都能解开，用馆长的公钥签名馆长验证不了；只有“馆长的公钥加密 + 你的私钥签名”三项都满足。
- **第 6 章**：公告 B 由仿冒者用自己的钥匙签名并附上自己的公钥，验证能通过，但公钥指纹和借书证背面印的不一致；公告 C 是图书馆签的，内容被改了一个字。
- **第 7 章**：`*.library.test` 不覆盖 `library.test` 本身；咖啡馆 Wi-Fi 上出示的是自签名证书；`library.test.login-check.example` 的证书完全合法，但网站不是 library.test。

## 判分

| 实验 | 提交内容 | 服务端怎么判 |
| --- | --- | --- |
| `mirror-lab` | 可以下载的镜像 + 原因 | 按官方指纹计算出安全的镜像集合，逐项比较 |
| `password-lab` / `symmetric-lab` / `public-lab` | 选择 | 用同一套计算重新评估每个场景 |
| `signature-lab` | 四条公告的判断 | 用玩具 RSA 验证签名、比对图书馆公钥指纹，得出应有的判断 |
| `certificate-lab` | 六个网站的判断 | 按证书链、有效期、域名规则计算应有的判断 |

## 修改须知

判分规则和期望结果写在 `simulation/` 里，平台的冻结检查只看 `validators.ts`，发现不了对它们的修改；改动指纹函数、密钥、公告文字或证书数据都会改变各章的答案。课程有学习记录后，这些都要按结构性变更处理，发布新 slug。
