# Git 版本控制：和别人一起改代码（`git-basics`）

**版本**：`1.0.0` · **格式**：Manifest `schemaVersion: 3` · **学习路线**：《计算机基础入门》第 5 门（前一门《命令行与文件系统》，路线最后一门）

## 设计思路

**一个世界**：library.test 网站的代码仓库 library-site。学生是开发**林可**，同事是**王磊**（小王）和**陈静**。整门课共用一段提交历史（7 次提交，从“初始化网站”到“借阅页标题改为‘我的借阅’”），每章从这段历史的某个时刻接着往下做。

**一个比喻**：照片档案。提交是给整个项目拍的一张快照，暂存区是取景框，分支是夹在某张照片上的书签，HEAD 是“你在这里”的箭头，远程仓库是大家共用的相册。

**在路线中的位置**：终端的用法接着上一门课；第 2 章的 `.env` 接着 HTTP 和命令行课里的数据库密码；仓库里改的就是前几门课里见过的那个网站。

## 模拟 Git

`simulation/git.ts` 是一个确定性的 Git，前端和服务端校验器共用：

- 快照式提交（每个提交保存完整文件树），提交号由内容哈希得出，同一段历史每次重放结果都一样。
- 工作区、暂存区、`.gitignore`；分支、HEAD、分离 HEAD；`HEAD~2`、`origin/main`、提交号前缀等写法。
- LCS 行级 diff 与 diff3 三方合并：只有一边改的自动合并，两边改同一处时写入 `<<<<<<<` / `=======` / `>>>>>>>` 标记并进入合并中状态。
- 一个远程仓库 `origin`：场景里同事的提交只在远程上，`fetch` 之后才看得到；推送不是快进时被拒绝，`--force` 会被记录下来。
- 命令：`status add commit log show diff restore reset revert branch switch checkout merge fetch pull push remote blame config`，输出和真实 Git 一样是英文。不讲 `stash` 和 `rebase`，遇到时给出中文说明。
- 只有一个极小的 shell：`ls`、`cat`、`echo 文字 > / >> 文件`、`rm`、`pwd`、`clear`、`help`，支持 `&&` 和 `;`。不执行任何真实命令，管道直接拒绝。
- 编辑器的“保存”也是一条操作，和命令一起记录。上限：60 步，每条命令 200 字符，每个文件 4000 字符，40 个文件，路径不能含 `..`。

`simulation/site.ts` 搭出各章开始时的仓库；`simulation/labs.ts` 是实验数据和判分规则。

## 几处刻意的设计

- **第 2 章**：`git add .` 会把 `.env` 和调试开关一起带进去；只要 `.env` 进过任何一个还能找到的提交就判不通过（用 `git reset` 撤掉、改正后可以通过）。提交说明是 `update`、`fix`、`修改` 之类也判不通过。
- **第 3 章**：改借阅期限的那次提交，说明写的是“调整样式”；说明里带“借阅”的提交反而都没碰 `config.js`。只看说明找不到，要看实际改动。
- **第 4 章**：调了一半的 `style.css` 在暂存区里，直接 `--amend` 会把它带进提交；`git reset --hard` 一把梭会把它丢掉；再做一次新提交而不是 amend，历史里会留下那次错别字提交。
- **第 5 章**：忘了先建分支，搜索功能就会提交到 main 上。
- **第 6 章**：冲突的那一行两边意图不同（工作日改成 21:00、新增周末时间），只留一边判不通过；把冲突标记一起提交也判不通过。另外两处不冲突的修改要自动合并进来。
- **第 7 章**：小王的提交只在远程上，`fetch` 之前本地看不到；`git push --force` 会把它抹掉。
- **第 8 章**：坏提交后面还有陈静和小王的两次提交，`reset --hard` 加强推会抹掉它们；工作区里还有没提交的草稿，`reset --hard` 会把它丢掉；`git revert HEAD` 撤错了提交。直接在编辑器里改好 `loans.js` 再提交推送也算修好，revert 是推荐做法。

## 判分

| 实验 | 提交内容 | 服务端怎么判 |
| --- | --- | --- |
| `history-lab` | 四个答案 | 提交号至少 7 位、与数据算出的提交号前缀一致；作者和文件为选项 |
| 其余六个 | 操作记录 | 在全新仓库上重放，按最终状态（各分支、远程、工作区、暂存区、事件记录）判分 |

“不该发生”的目标（没有强推、`.env` 没进历史、没有遗留冲突标记等）只在主要操作完成之后才可能变绿，避免初始状态出现虚假的通过。

## 修改须知

判分规则写在 `simulation/` 里，平台的冻结检查只看 `validators.ts`，发现不了对它们的修改。提交号由内容哈希得出：改动 `site.ts` 里的任何文件内容、作者或时间，第 3 章的答案都会变。课程有学习记录后，这些都要按结构性变更处理，发布新 slug。
