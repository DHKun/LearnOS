## 毕业设计_最终版_真的最终版

你一定见过这样的文件夹：`报告.docx`、`报告_改.docx`、`报告_最终版.docx`、`报告_最终版2_别删.docx`。哪个是最新的？上周那版改了什么？同事改的和你改的怎么合到一起？

写代码比写报告更麻烦：一个网站有几十个文件，三个人同时在改。**版本控制**就是专门解决这件事的工具，现在几乎所有软件项目都用 **Git**。

## Git 记下的是什么

每当你觉得“这一版可以了”，就做一次**提交**（commit）。提交会记下：

- 这一刻**所有文件**的样子；
- 一句**说明**：这次改了什么、为什么改；
- **作者**和**时间**；
- **上一次提交**是哪一个。

一次次提交串起来，就是项目的历史。每个提交有一个由内容算出来的编号，比如 `2b25c82`。

## 这门课的项目

整门课都在同一个仓库里：**library-site**，也就是 library.test 网站的源代码。你是开发**林可**，同事是**王磊**（小王）和**陈静**。前几门课里你见过这个网站的请求、网络和服务器，这门课看它的代码是怎么一步步改出来的。

实验里有三样东西：

- **编辑器**：选中一个文件直接修改，点“保存”后写进工作区；
- **终端**：输入 `git` 命令，输出和真实的 Git 一样是英文；
- **提交图**：实时画出所有提交和分支。

都在浏览器里模拟，随时可以清空记录重来。
