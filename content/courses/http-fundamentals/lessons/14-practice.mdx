## 综合实验：你现在是一个 API 客户端

前面的章节分别讨论 URL、方法、Header、Body、Cookie 和响应。本章把这些知识组合起来，完成三个连续任务。全部实验仍在浏览器中模拟，不会访问真实网络。

### 任务一：获取书籍

使用 `GET /api/books/2` 读取编号为 2 的书籍，确认响应是 200，并能指出返回的 JSON 代表什么。

### 任务二：创建便签

使用 `POST /api/notes`，添加 `Content-Type: application/json`，并发送形如 `{"title":"我的 HTTP 笔记"}` 的 JSON。观察为什么创建成功时经常使用 201，而不是一律 200。

### 任务三：读取登录用户资料

使用 `GET /api/profile` 并附上教学专用 `Cookie: session=learnos-demo`。如果没有 Cookie，虚拟服务器会返回 401；加入有效示例会话标识之后返回 200。

## 操作工作台

你可以逐项选择方法、路径、正文类型和 Cookie，点击“运行本地模拟”，观察响应。每项满足预设条件后点击“验证当前任务”，由服务端独立重算并保存结果。

## 实验结束后你应该能做到

- 看到 401，能推断优先检查认证凭据，而非猜测服务器已经宕机。
- 看到 415，能解释 Content-Type 与 Body 格式的关系。
- 看到 201，能确认服务器已创建资源并尝试寻找 Location。
- 能分清演示中的 JS 模拟反馈与正式由服务端记录的实验通过状态。
