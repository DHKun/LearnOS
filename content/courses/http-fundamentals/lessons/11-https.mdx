## HTTP 和 HTTPS 到底是什么关系？

HTTPS 不是一套与 HTTP 完全不同的网页业务语义。简单说，它是在通信通道受到 TLS 保护的情况下使用 HTTP。

对于用户来说，地址栏中的 `https://` 通常意味着浏览器要建立具备加密和身份认证能力的安全连接。具体协议栈可能是 HTTP/1.1 或 HTTP/2 经 TCP/TLS，也可能是 HTTP/3 经 QUIC/TLS。

## HTTPS 主要保护哪些方面？

- **机密性**：网络中间人不应轻易读取被保护的 HTTP 内容。
- **完整性**：传输过程中的篡改能够被检测到。
- **服务器身份认证**：借助证书及信任链，浏览器验证自己是否在与目标站点建立安全连接。

证书验证失败、使用不可信证书、设备受到恶意根证书影响等情况会改变安全边界。本课不深入 TLS 密码套件与握手字节格式。

## HTTPS 不保证什么？

HTTPS **不能自动修复**弱密码、XSS、SQL 注入、越权、错误的权限设计，也不能阻止网站自己记录访问内容。它保护传输，不保证服务本身没有漏洞。

HTTPS 也不代表所有元数据都完全隐藏。网络层仍可能观察到连接目标的某些信息；DNS 和 SNI 等隐私行为取决于具体部署与所用协议能力。

<Callout type="tip" title="你应该形成的心智模型">
TLS 负责建立可信的安全通道；HTTP 负责表达“请求什么、如何响应”。不要把“加密”与“授权”当作同一回事。
</Callout>

## 开发者实际应该怎样做？

生产站点通常应使用有效的可信证书、正确配置 HTTPS、保护会话 Cookie，并防止从安全页面加载不安全资源。客户端不要无条件忽略证书错误。
