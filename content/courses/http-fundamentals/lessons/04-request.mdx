## 请求是浏览器发给服务器的“任务说明”

当我们说“发送 HTTP 请求”，重点不是点击按钮这个动作，而是一条具有结构的消息。先观察一个示意报文：

```http
GET /api/books/2 HTTP/1.1
Host: api.example.test
Accept: application/json

```

## HTTP/1.1 请求长什么样？

请求报文的第一行称为请求行，包含三部分：

- **方法 Method**：希望执行什么操作，例如 GET。
- **请求目标 Request Target**：希望操作哪个资源，例如 `/api/books/2`。
- **协议版本**：此处用 HTTP/1.1 的文本形式展示。

接下来是 Header。`Host` 指定目标主机，`Accept` 表达希望收到什么类型的表示。空行之后可以有 Body，也可以没有。

```http
POST /api/notes HTTP/1.1
Host: api.example.test
Content-Type: application/json
Accept: application/json

{"title":"今天学会了 HTTP"}
```

第二条请求的 Body 是一段 JSON。它是**客户端提交的数据**，不是 HTTP 协议要求每个请求都必须携带的内容。

## 真实理解：请求不是按路径自动成功的

请求目标、方法、Header 和 Body 组合起来，才能说明客户端到底要做什么。`GET /api/books/2` 和 `DELETE /api/books/2` 面向相同资源，却具有完全不同的语义。
