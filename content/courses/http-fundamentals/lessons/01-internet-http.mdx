## 这一章要解决什么问题？

你在浏览器中输入一个网址，按下回车，屏幕上出现一个页面。这看上去像是在“打开一个文件”，实际上通常是**浏览器与远端服务交换信息**的结果。

本章不要求你会写代码。学完后，你应该能够指出：谁发出请求、谁处理请求，以及 HTTP 在整个过程中负责哪一部分。

## 从一个生活场景开始

想象你走进图书馆，要借一本书：

1. 你向工作人员说明要借哪本书。
2. 工作人员根据书名或编号检索馆藏。
3. 工作人员给你书，或告诉你书不存在、暂时借不了。

Web 系统也常采用类似模式：**浏览器是客户端，提供资源和处理逻辑的一方是服务器**。浏览器发出请求（Request），服务器返回响应（Response）。

## HTTP 究竟是什么？

HTTP 的英文全称是 *Hypertext Transfer Protocol*，中文常译作**超文本传输协议**。虽然名字带有“超文本”，现代 HTTP 并不只传 HTML 页面，还经常传图片、CSS、JavaScript、JSON 数据等。

HTTP 主要规定双方交换的消息具有什么语义：客户端请求什么资源、采用什么方法、附带哪些信息；服务器应如何表示处理结果。HTTP 本身**不负责把域名变成 IP，也不等于 TCP 或 TLS**，这些属于不同层次。

<Callout type="note" title="不要混淆">
浏览器、服务器是参与通信的角色；HTTP 是双方约定的通信规则。服务器既可以返回网页，也可以只返回一份 JSON 数据。
</Callout>

## 浏览器打开页面时到底发生了什么？

下面只是先建立全局认识，后面的章节会逐一拆开：

```text
输入 https://example.test/news
       ↓
浏览器确定目标站点并准备连接
       ↓
浏览器发送 HTTP 请求
       ↓
服务器处理请求并返回 HTTP 响应
       ↓
浏览器解析 HTML，并可能继续请求 CSS、JS 和图片
       ↓
把网页绘制到屏幕上
```

一个网页可能需要几十次甚至更多次 HTTP 请求，并不是一次请求把所有内容都拿到。

## 记住三个关键词

| 名称 | 一句话解释 | 例子 |
| --- | --- | --- |
| Client | 发起请求的一方 | 浏览器、移动 App |
| Server | 处理请求并返回结果的一方 | 网站后端、图片服务 |
| HTTP | 表达请求和响应语义的一套规则 | GET、200、Header |

**自我思考**：打开页面后，图片逐渐出现。如果 HTML 已经返回了，为什么图片还可能继续加载？答案是 HTML 经常引用了其他资源，浏览器会为它们再发起请求。
