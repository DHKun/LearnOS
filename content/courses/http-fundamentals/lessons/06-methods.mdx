## 同一个资源，为什么要使用不同方法？

`/api/books/2` 可以被读取、修改或删除。请求方法用来声明操作语义，服务器据此路由和执行。

| 方法 | 典型用途 | 标准语义是否安全 | 标准语义是否幂等 |
| --- | --- | --- | --- |
| GET | 读取资源 | 是 | 是 |
| HEAD | 与 GET 类似，但不返回响应正文 | 是 | 是 |
| POST | 交付数据供目标资源处理、创建等 | 否 | 通常否 |
| PUT | 创建或整体替换目标资源的表述 | 否 | 是 |
| PATCH | 对资源做局部修改 | 否 | 不保证 |
| DELETE | 删除目标资源 | 否 | 是 |

“安全”指客户端没有请求改变服务器状态的语义；并非防攻击或加密。“幂等”指重复相同请求，其**预期对服务器状态产生的效果**与单次相同，并不意味着每次都返回完全一样的响应状态码。

## 为什么重试有时会产生两次订单？

一个典型场景是：客户端发送 `POST /orders`，服务器已经创建订单，但响应在网络中丢失。客户端以为失败又重试，可能产生第二笔订单。解决办法通常需要业务层的幂等键、唯一约束等机制，而不能只靠“POST 也是 HTTP”。

```text
POST /orders（第 1 次）→ 服务器创建订单 #101 → 响应丢失
POST /orders（重试）   → 服务器又创建订单 #102
```
