## 页面出问题时，先不要猜

你可以通过浏览器开发者工具的 **Network（网络）** 面板观察真实请求。平时按 F12 或使用浏览器菜单打开开发者工具，再刷新页面，通常能看到发出的请求列表。

一次排查至少应该关注：

1. **Request URL**：请求是否发向预期地址？
2. **Method**：是不是错误地使用了 GET、POST 等方法？
3. **Status**：200、401、403、404、405、415、500 哪种情况？
4. **Request Headers / Payload**：凭据、媒体类型、请求体是否正确？
5. **Response Headers / Body**：服务端提供了什么线索？
6. **Timing**：问题是否发生在连接、等待响应或资源下载等阶段？

## 一个实用的排错顺序

| 现象 | 优先考虑 |
| --- | --- |
| URL 和预期不一致 | 网址拼写、路径、查询参数 |
| 返回 401 | 登录凭据是否存在、是否有效 |
| 返回 403 | 登录成功后是否有足够权限 |
| 返回 404 | 目标资源路径是否存在 |
| 返回 405 | 当前资源是否支持该 HTTP 方法 |
| 返回 415 | 请求 Content-Type 是否符合 API 预期 |
| 返回 500 | 服务器日志和异常，而不是反复刷新猜测 |

<Callout type="warning" title="抓包和隐私">
Network 面板可能显示个人 Cookie、Authorization Token 等敏感数据。截图分享或复制 HAR 文件前必须脱敏。
</Callout>

## 真实世界中还要看什么？

如果状态码根本没有出现，问题可能不是 HTTP 业务规则，而是在域名解析、连接、TLS 握手、浏览器策略或网络环境。应先确认失败发生在哪一层。
