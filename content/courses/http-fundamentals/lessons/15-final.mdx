## 回顾：从输入网址到理解响应

恭喜来到最后一章。回忆整条链路：

```text
URL → 定位服务器与建立连接 → HTTP Request
    → 服务器处理 → HTTP Response → 浏览器处理结果
```

现在你应该能看懂一个基本 HTTP/1.1 请求行、判断常见状态码、区分 Accept 和 Content-Type、解释 Cookie 的用途，以及理解为什么 HTTPS 和权限校验缺一不可。

## 十个最重要的判断

1. HTTP 描述请求与响应的语义，不等于 DNS、TCP 或 TLS。
2. URL 的 Query 与 Fragment 不同，Fragment 通常不发给服务器。
3. HTTP 1.1 文本报文不是 HTTP/2 或 HTTP/3 的线上格式。
4. GET 的安全性是语义约定，不等于天然不会发生副作用。
5. PUT 和 DELETE 幂等，不代表重复请求必然返回相同状态码。
6. `Accept` 是客户端希望得到什么，`Content-Type` 是这条消息携带的表示是什么。
7. `401` 与认证有关，`403` 常与授权拒绝有关。
8. `HttpOnly` 让 JS 无法读取相应 Cookie，但不会消除全部 XSS 风险。
9. HTTPS 保护传输，不替代服务器对用户权限的校验。
10. `304` 帮助复用缓存，不是普通的服务端错误。
