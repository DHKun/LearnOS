## HTTP 是无状态的，网站为什么还记得我登录过？

HTTP 协议本身不会自动记住两个请求属于同一个用户。很多网站使用会话（Session）与 Cookie 来维持访问体验。

一个常见的登录过程是：服务器验证账号信息后，创建服务端会话，再通过响应头要求浏览器保存一个会话标识。

```http
HTTP/1.1 200 OK
Set-Cookie: session=demo-123; Path=/account; Secure; HttpOnly; SameSite=Lax
```

之后，访问满足 Cookie 适用条件的目标时，浏览器可能自动在请求头中携带：

```http
Cookie: session=demo-123
```

## Cookie 属性的真正作用

| 属性 | 作用 | 常见误解 |
| --- | --- | --- |
| `Path` | 规定目标路径的匹配范围 | `/account` 不意味着任意路径都携带 |
| `Secure` | 只在符合安全传输条件时发送，生产会话 Cookie 应使用 | 不会自动把 HTTP 升级为 HTTPS |
| `HttpOnly` | 禁止页面 JavaScript 读取该 Cookie | 不能单独阻止所有 XSS 后果 |
| `SameSite` | 对跨站情境下的 Cookie 发送设置限制 | 不等于 CORS，也不是全面 CSRF 防护 |
| `Expires` / `Max-Age` | 决定 Cookie 生命周期 | 不等于服务器端会话必然同一时刻过期 |

`SameSite=None` 在现代浏览器中通常要求 `Secure`，否则 Cookie 可能被拒绝。本课不会尝试模拟所有浏览器兼容性细节。

## 安全边界

Cookie 的值通常只是会话标识，**不是证明“自己有权限”的充分依据**。服务器必须验证这个标识是否有效，再依据服务端的用户身份与权限执行请求。

<Callout type="warning" title="示例值永远不是真正的密钥">
`demo-123` 是本地模拟值，不是真实账号凭据。不要把实际 Session ID 粘贴到公共讨论或课程笔记中。
