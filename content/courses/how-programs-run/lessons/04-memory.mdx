## 多打了 10 行的成绩单

补考之后，每人加 10 分，再打印成绩单。成绩单打出来 15 行，后面一串都是 0，班级人数也从 5 变成了 15。问题出在一个“多走了一格”的循环上。

## 地址和数组

内存是一排编了号的格子。**数组**就是一排挨着的格子：5 个成绩放在 `[30]`～`[34]`，第 i 个成绩在 `30 + i`。紧挨着的 `[35]` 放的是另一样东西：人数。

## 用寄存器当指针

格子机可以把寄存器里的数当成地址用：

```text
SET R1, 30       ; R1 指向第一个成绩
LOAD R0, [R1]    ; 读 R1 指着的那一格
ADD R1, 1        ; 指向下一格
```

存着地址的寄存器（或变量）叫**指针**。

## 越界

机器并不知道哪几格属于数组。循环条件写错一点，指针走到 `[35]`，`STORE` 照样会写进去，不会有任何报错，旁边的数据就悄悄被改了。这类错误叫**越界写入**，也叫**缓冲区溢出**。在真实的程序里，它会让程序算错、崩溃，严重时还会被人利用来控制程序，是最常见也最危险的一类 bug。
