# 程序是怎么跑起来的：CPU、内存与操作系统（`how-programs-run`）

**版本**：`1.0.0` · **格式**：Manifest `schemaVersion: 3` · **学习路线**：《计算机基础入门》第 2 门（前一门《0 和 1 的世界》，后一门《网络基础》）

## 设计思路

**一个世界**：一台模拟的教学计算机“格子机”。4 个寄存器（R0～R3）、程序计数器 PC、Z / N 两个标志位、64 格内存（每格一个整数）、从地址 63 往下长的栈。全课的实验都在这台机器上做：结账程序、求和循环、成绩数组、函数调用，最后加上缓存和一个调度器。

**一个比喻**：厨房。CPU 是厨师，寄存器是手边的砧板，内存是储物架，硬盘是楼下仓库，程序是菜谱，PC 是按在菜谱上的手指，栈是一摞盘子，缓存是手边的小台面，操作系统是安排各桌订单的经理。

**在路线中的位置**：接着《0 和 1 的世界》讲“这些 0 和 1 是怎么被执行的”；第 7 章的进程为《命令行与文件系统》里的 `ps`、`kill` 打底；第 4 章的越界写入是以后安全课程里内存安全问题的起点。

## 格子机

`simulation/machine.ts`：汇编器 + 解释器，前端和服务端校验器共用。

| 指令 | 作用 |
| --- | --- |
| `SET R, n` / `MOV R, R` | 赋值 |
| `LOAD R, [a]` / `LOAD R, [R]` | 从内存读（直接地址或寄存器间接） |
| `STORE R, [a]` / `STORE R, [R]` | 写内存 |
| `ADD` / `SUB` / `MUL R, R 或 n` | 算术，更新标志位 |
| `CMP R, R 或 n` | 比较，更新标志位 |
| `JMP` / `JZ` / `JNZ` / `JLT` / `JGE 标签` | 跳转 |
| `CALL 标签` / `RET` / `PUSH R` / `POP R` | 函数调用与栈 |
| `OUT R` / `HALT` | 输出、停机 |

- 只认识这 19 条指令，**不执行任何真实代码**。程序最多 60 行、每行 80 字符，最多运行 2000 步。
- 越界读写、写进栈区、栈满（用到 40 以下）、栈空时 `POP` / `RET`、`RET` 取到的不是指令位置、走出程序末尾，都会以中文报错停下，并指出第几行。
- `trace()` 记录每一步的完整状态，供调试器前进、后退。
- `simulateCache()`：直接映射缓存（4 行 × 4 格，命中 1 周期，未命中 20 周期）。
- `simulation/scheduler.ts`：单核调度模拟，毫秒为单位，每次切换 1 毫秒；先来先服务、短作业优先（不可抢占）、轮转（时间片 2 / 5 / 10 / 30 毫秒）。

## 几处刻意的设计

- **第 2 章**：小计在加包装费**之前**写入 [20]，最容易误答成加了包装费之后的值；第 4 题要求自己把数量改成 1 重新运行，才能看出 `JZ` 的作用。
- **第 3 章**：初始程序“先做后判断”，N = 10 时少加最后一个数，N = 0 时得到 1。服务端用 N = 10、1、0、7 四组测试。正文的示例换成了结构相同的倒数打印，避免直接给出答案。
- **第 4 章**：循环条件 `CMP R1, 36` 多走一格，把人数 [35] 从 5 改成 15，打印出 15 行。服务端检查执行过程中有没有写过 [35]，事后再把人数改回 5 也判不通过。
- **第 5 章**：函数 `PUSH R1` 后没有 `POP`，`RET` 把 R1 的旧值当成返回地址跳回去，反复调用直到栈满。`POP R0` 这类“配对但恢复错了寄存器”的改法同样判不通过。
- **第 6 章**：三处各自对应一种未命中：按列遍历（空间局部性差）、结构数组里跳着读一个字段、两个数组映射到同一缓存行（冲突未命中）。
- **第 7 章**：参数经过校准，只有“轮转 + 5 毫秒时间片”能全部满足；先来先服务和短作业优先卡住键盘和视频，2 毫秒切换开销超标，10 毫秒键盘慢 2 毫秒，30 毫秒视频卡顿。

## 判分

| 实验 | 提交内容 | 服务端怎么判 |
| --- | --- | --- |
| `trace-lab` | 四个答案 | 与解释器运行结果比较 |

## 修改须知

判分规则写在 `simulation/` 里，平台的冻结检查只看 `validators.ts`，发现不了对它们的修改；改动指令语义、测试输入、缓存参数或调度参数都会改变各章的答案。课程有学习记录后，这些都要按结构性变更处理，发布新 slug。
