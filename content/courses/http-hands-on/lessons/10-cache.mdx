## 为什么需要缓存

同一个 JS 文件、同一张图片，如果每次打开页面都重新下载，既慢又费流量。缓存让浏览器把副本存起来。难点在于：**什么时候可以直接用副本，什么时候必须问一下服务器。**

## 常用的缓存规则

| 响应头 | 意思 |
| --- | --- |
| `Cache-Control: max-age=600` | 600 秒内直接用副本，连请求都不发 |
| `Cache-Control: no-cache` | 可以存副本，但**每次使用前都要先问服务器**（通常得到 304） |
| `Cache-Control: no-store` | 根本不存。用于敏感数据 |
| `Cache-Control: private` | 只允许浏览器存，CDN 等共享缓存不能存 |
| `immutable` | 和长 `max-age` 一起用：这份内容永远不会变 |
| `ETag` + `If-None-Match` | 版本号，以及「还是这个版本吗？」的条件请求 |

`no-cache` 的名字很有误导性：它的意思是「先验证再用」，不是「不缓存」。

## 前端常见做法：文件名带哈希

构建工具会把文件内容的哈希写进文件名，比如 `app.3f9a.js`。内容一变，文件名就变成 `app.8c21.js`，对浏览器来说是一个全新的地址。所以这类文件可以放心地缓存一年。而引用它们的 HTML 必须每次验证，否则用户会一直拿着旧 HTML、加载旧 JS。
