## 先看一个现象

打开网页时，内容常常是一块一块冒出来的：先是文字，再是图片，最后某个角落的数据才出现。有时整个页面都好好的，偏偏「我的借阅」是空的。

要解释这些现象，得先知道按下回车之后发生了什么。整门课都围绕一个模拟网站 **library.test**（一座小图书馆的网站）展开：你会读它的请求、修它的故障，最后亲手调用它的 API，帮一位读者借到一本书。

## 其实是三件不同的事

| 步骤 | 由谁负责 | 解决什么问题 |
| --- | --- | --- |
| 找到服务器 | DNS | 把 `library.test` 换成 IP 地址 |
| 建立通道 | TCP（或 QUIC）+ TLS | 可靠、加密地传输数据 |
| 说清楚要什么 | **HTTP** | 请求哪个资源、做什么、结果如何 |

这门课讲的是第三件。前两件出问题时，你**根本看不到 HTTP 状态码**，因为请求还没发出去。第 11 章排错时，这一点很关键。

## 一个页面 = 很多次请求

浏览器拿到 HTML 后，会发现里面引用了样式表、脚本、图片，于是为每一个再发请求。脚本运行起来，还会调用 API 去取数据。所以：

- 页面「打开了」，只说明 HTML 那一个请求成功了；
- 列表是空的、图片裂开，往往是其中某一个子请求失败了。

## 现在就看一眼真实的请求（可选）

浏览器的**开发者工具**里有一个 **Network（网络）面板**，会把页面发出的每一个请求列出来。试试：

1. 按 `F12`（Mac 上是 `Cmd + Option + I`）打开开发者工具；
2. 切到 **Network** 标签；
3. 刷新这一页。

你会看到 LearnOS 自己发出的几十个请求。其中有一个名为 `heartbeat` 的请求，在页面处于活动状态时大约每分钟出现一次，平台靠它记录你最近一次在线的时间。

<Callout type="warning" title="别把请求截图随手发出去">
Network 面板里能看到你的 Cookie 等登录凭据。截图或复制给别人之前，先把这些值遮掉。
</Callout>

## 小结

- 按下回车后：DNS 找地址 → 建立连接 → HTTP 请求与响应。
- HTTP 只管「要什么、结果如何」。
- 一个页面由很多请求组成，每一个都可能单独失败。
