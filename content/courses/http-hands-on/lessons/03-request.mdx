## 请求长什么样

HTTP/1.1 的请求是一段有固定格式的文本。先一行一行看：

<ConceptPlayer conceptId="http-hands-on/message" blockId="message-anatomy" />

一条请求由四部分组成：

1. **请求行**：方法、请求目标、协议版本，例如 `GET /api/books/2 HTTP/1.1`；
2. **请求头**：每行一个 `名称: 值`，名称不区分大小写；
3. **空行**：表示头部结束；
4. **正文**（可选）：GET 一般没有正文，提交数据时才会有。

<Callout type="note" title="HTTP/2 和 HTTP/3 呢？">
它们在网络上传的是二进制帧，不是这样的文本，但方法、目标、头部、状态码这些含义完全相同。开发者工具也会按这种格式显示给你看，所以学会读 HTTP/1.1 文本就够了。
</Callout>

## 资源有自己的地址

API 会为每一类资源规定地址，客户端必须按约定来请求，服务器不会替你猜：

| 地址 | 含义 |
| --- | --- |
| `/api/books` | 图书集合（列表），支持 `?q=` 搜索、`?page=` 翻页 |
| `/api/books/2` | 集合里 ID 为 2 的那一本 |

## 小结

- 请求 = 请求行 + 请求头 + 空行 + 可选正文。
- 地址由 API 设计决定。遇到 404，先核对地址是否符合 API 约定，再怀疑别的。
