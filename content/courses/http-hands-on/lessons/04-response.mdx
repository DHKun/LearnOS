## 响应：服务器的回执

响应的结构和请求一样：**状态行 → 响应头 → 空行 → 可选正文**。状态行里最重要的是三位数的状态码。

## 先看首位数字：谁该行动

| 家族 | 意思 | 常见的码 | 谁来处理 |
| --- | --- | --- | --- |
| 2xx | 成功 | 200 OK，201 Created，204 No Content | 无需处理 |
| 3xx | 去别处，或用你已有的副本 | 301、302 重定向，304 Not Modified | 浏览器通常自动处理 |
| 4xx | 请求这边有问题 | 400、401、403、404、405、409、415 | 客户端修改请求 |
| 5xx | 服务器出了问题 | 500、502、503 | 服务器端排查 |

## 首位数字只是开始，细节在头部里

状态码告诉你大方向，**具体该怎么做，往往写在响应头和正文里**：

- `201 Created` 常带 `Location`：新资源的地址；
- `301` / `302` 带 `Location`：要去的新地址；
- `405 Method Not Allowed` 带 `Allow`：这个资源支持哪些方法；
- `503 Service Unavailable` 可能带 `Retry-After`：多久之后再试；
- `Content-Type` 说明正文是什么格式，决定客户端该怎么解析。

## 三个常见误会

- **200 不代表拿到了你想要的东西**：没登录时，有些网站会返回 200 加一张 HTML 登录页，前端按 JSON 解析就会报错。
- **4xx 不是服务器坏了**：它是服务器在明确告诉你「请求有问题」。
- **5xx 别反复刷新**：记下请求时间和响应里的 requestId（如果有），交给后端去查日志。
