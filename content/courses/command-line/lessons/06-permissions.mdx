## 上线前的检查

网站上线前过一遍：首页打不开、上传总失败、部署脚本运行不了；实习生还说他能看到数据库密码。这四件事都是同一个原因：**权限**。

## 读懂 ls -l

```text
-rw-r----- 1 ops web 67 Oct 27 07:00 db.env
```

第一个字符表示类型：`-` 是文件，`d` 是目录。后面九个字符分成三组：

| `rw-` | `r--` | `---` |
| --- | --- | --- |
| 主人（ops）能读写 | web 组的成员能读 | 其他人什么都不能做 |

再往后是主人 `ops` 和所属组 `web`。用 `id` 可以看到一个用户在哪些组里。

## 三种权限，文件和目录不一样

| | 对文件 | 对目录 |
| --- | --- | --- |
| `r` | 读内容 | 列出里面有哪些名字 |
| `w` | 修改内容 | 在里面新建、删除、改名 |
| `x` | 当作程序运行 | **进入**它，访问里面的东西 |

目录的 `x` 最容易被忽略：要读 `/srv/library/config/db.env`，路上的 `/srv`、`/srv/library`、`/srv/library/config` 每一层都要有 `x`。

## 数字写法和 chmod

每组三位按 r=4、w=2、x=1 相加，三组连起来就是三位数：

| 数字 | 字母 | 常见用途 |
| --- | --- | --- |
| `644` | `rw-r--r--` | 普通文件：自己能改，别人能看 |
| `640` | `rw-r-----` | 只给同组看的配置文件 |
| `600` | `rw-------` | 只有自己能看的私密文件 |
| `755` | `rwxr-xr-x` | 程序、谁都能进的目录 |
| `750` | `rwxr-x---` | 只让同组进的目录 |
| `775` | `rwxrwxr-x` | 同组也能往里写的目录 |

```bash
chmod 640 db.env       # 用数字直接设
chmod u+x deploy.sh    # 给主人加上 x
chmod o-r db.env       # 去掉其他人的 r
```

只有文件的主人（和管理员）能改它的权限。

## 开够就好

`chmod 777` 能让“权限问题”立刻消失，同时也让服务器上任何一个用户、任何一个被攻破的程序都能改你的文件。正确的做法是想清楚**谁**需要**做什么**，只开这些。
