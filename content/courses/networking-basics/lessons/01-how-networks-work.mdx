## 一个问题

你在浏览器里打开 library.test，一张图片从几百公里外的机房来到你的屏幕上，前后不到一秒。中间经过了谁？它们怎么知道往哪送？

这门课用一座模拟的“小城”回答这个问题：你的家、家门口的路由器、运营商、分公司的办公室，还有 library.test 所在的机房。每一章修好小城里的一个网络故障。

## 三件事

上一门课讲过，计算机里的一切都是字节。网络要解决的，是把这些字节从一台机器送到另一台：

1. **拆成小包**：大块数据被拆成一个个几百到一千多字节的**数据包**，每个包独立上路。
2. **贴好标签**：每个包都写着“给哪台机器”（**IP 地址**）、“给机器上的哪个程序”（**端口**）、“这一段路交给谁”（**MAC 地址**）。
3. **逐站转发**：一路上的每台**路由器**只看 IP 地址，决定把包交给下一站。

| IP 地址 | 找到哪台机器 | 第 2、4 章 |
| MAC 地址 | 局域网里这一段交给谁 | 第 3 章 |
| 端口 | 交给机器上的哪个程序 | 第 6 章 |
| 域名 | 方便人记的名字，用 DNS 换成 IP | 第 5 章 |

## 为什么要拆成小包

- **共享线路**：很多人的数据可以交错着走同一条线，谁也不用等别人整块传完。
- **出错代价小**：一个小包坏了或丢了，只重发这一个，不必重传整个文件。上一门课的校验和，就是用来发现包坏了没有的。
- **可以绕路**：某条线路断了，后面的包可以从别的路走。
