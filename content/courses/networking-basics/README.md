# 网络基础：数据包怎么到达（`networking-basics`）

**版本**：`1.0.0` · **格式**：Manifest `schemaVersion: 3` · **学习路线**：《计算机基础入门》第 2 门（前一门《0 和 1 的世界》，后一门《HTTP 实战》）

## 设计思路

**一个世界**：一座模拟的“小城”：你的家（192.168.1.0/24）、家门口的路由器、运营商、分公司办公室（10.8.1.0/24）和总部、library.test 所在的机房。每一章修好小城里的一个网络故障，后面的章节继续用前面的设定。

**一个比喻**：寄快递。IP 是收件地址，MAC 是这一段由哪位快递员送，端口是房间号，路由器是分拣站，DNS 是查号台，NAT 是公司前台的登记本。

**在路线中的位置**：比特、字节、二进制、校验和在上一门课讲过，这里直接使用；HTTP 留给下一门。第 5 章 DNS 是 HTTP 课“按下回车之后”的展开。

**地址都是“假的”**：公网地址用 RFC 5737 的文档专用地址段（`203.0.113.0/24`、`198.51.100.0/24`、`192.0.2.0/24`），域名用保留的 `.test`，不会和真实网络冲突。

## 几处刻意的设计

- **第 4 章**：初始路由表让“去总部”碰巧是通的、“去外网”在两台路由器之间打转。学生把默认路由改对后，总部反而断了（私有地址被运营商丢弃），必须理解最长前缀匹配才能两边都通。
- **第 6 章**：既要开够（语音是 UDP，开 TCP 3478 没用），又不能多开（SSH 只对办公室开放，数据库不对外）。
- **第 8 章**：场景分“现在”和“路由器重启之后”两列。不做 DHCP 地址保留，重启后两台设备地址对调，转发指向了错误的设备。没有时间维度，地址保留这个设置就没有可观察的效果。
- **第 9 章**：记录里混入了“看起来吓人但正常”的跳（中间一跳不回话、一跳延迟高但后面恢复）。
- **第 10 章**：只给一个模拟命令行（`ipconfig`、`ping`、`nslookup`、`arp -a`、`curl`），不给实时的对错提示，学生要自己验证。
